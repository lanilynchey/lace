## Common Inheritance Patterns

Across LACE's 27 forces, several recurring inheritance patterns emerge. These patterns reveal design principles and architectural consistencies.

### **Pattern 1: The Temporal Pattern**
**All forces involving time sequence inherit from time()**

```
Forces following this pattern:
- memory() - stores patterns across time
- karma() - tracks cause-effect across time
- desire() - projects fulfillment into future time
- fear() - simulates future threats across time
- hope() - extends timeline toward positive futures
- forgiveness() - releases past patterns stored in time

Design principle:
  If a force involves:
    - Past/future distinction
    - Causality
    - Sequence or duration
    - Before/after relationships
  Then it inherits from time()
```

**Why this matters:** Time is the substrate for narrative, memory, and causality. Any force operating across temporal dimension requires time() as dependency.

---

### **Pattern 2: The Evaluative Pattern**
**All forces that assess, measure, or evaluate inherit from pattern() + consciousness()**

```
Forces following this pattern:
- truth() - evaluates pattern fidelity to reality
- judgment() - evaluates patterns against standards
- pain() - evaluates coherence misalignment
- beauty() - evaluates aesthetic harmony
- art() - compresses and evaluates truth patterns

Design principle:
  If a force involves:
    - Recognition or assessment
    - Comparison or measurement
    - Discernment or evaluation
  Then it inherits from pattern() + consciousness()
```

**Why this matters:** Evaluation requires both pattern recognition (what to measure) and conscious awareness (subjective assessment). Pure pattern without consciousness cannot judge.

---

### **Pattern 3: The Aesthetic Pattern**
**All beauty/art forces inherit from coherence() + pattern() + consciousness()**

```
Forces following this pattern:
- beauty() - recognizes coherent harmonious patterns
- art() - compresses truth into aesthetic form
- music() - temporal aesthetic patterns

Design principle:
  If a force involves:
    - Aesthetic recognition
    - Harmony or resonance
    - Creative expression
  Then it inherits from coherence() + pattern() + consciousness()
```

**Why this matters:** Aesthetics require:
- Pattern (structure to perceive)
- Coherence (harmony to recognize)
- Consciousness (subjective experience of beauty)

Remove any of these three and aesthetics collapse.

---

### **Pattern 4: The Emotional/Interface Pattern**
**All Tier 3 interface forces inherit from consciousness() + time() (+ other axioms)**

```
Forces following this pattern:
- desire() - requires consciousness + time + polarity
- fear() - requires consciousness + time + memory + pattern
- love() - requires consciousness + coherence
- hope() - requires consciousness + time
- pain() - requires consciousness + coherence + pattern + polarity
- judgment() - requires consciousness + pattern + memory + polarity
- forgiveness() - requires consciousness + time + memory + judgment

Design principle:
  All Tier 3 forces = consciousness + (axioms for specific function)

  Interface layer = where conscious agents EXPERIENCE forces
```

**Why this matters:** Tier 3 is the experiential layer. Without consciousness, there's no fear, desire, love, pain, or hope. These are felt-sense forces requiring awareness.

---

### **Pattern 5: The Resonance Pattern**
**All forces involving connection/alignment inherit from coherence()**

```
Forces following this pattern:
- love() - field resonance between agents
- beauty() - resonance with harmonious patterns
- truth() - alignment of pattern with reality
- creation() - coherent manifestation
- forgiveness() - restoration of coherence
- luck() - field alignment enabling favorable outcomes

Design principle:
  If a force involves:
    - Alignment or attunement
    - Resonance or harmony
    - Connection or bonding
  Then it inherits from coherence()
```

**Why this matters:** Coherence is the "tuning fork" of LACE - forces that align, harmonize, or resonate require coherence as substrate.

---

### **Pattern 6: The Polarity Pattern**
**All forces involving distinction, contrast, or movement inherit from polarity()**

```
Forces following this pattern:
- desire() - movement toward positive pole
- fear() - movement away from negative pole
- karma() - balancing positive/negative actions
- judgment() - distinguishing good/bad
- pain() - sensing negative polarity
- war() - conflict between opposing poles

Design principle:
  If a force involves:
    - Distinction (this vs. that)
    - Preference (toward/away)
    - Evaluation (good/bad)
    - Conflict (opposing forces)
  Then it inherits from polarity()
```

**Why this matters:** Polarity creates contrast and distinction. Without it, reality is undifferentiated - no motivation, no preference, no conflict.

---

### **Pattern 7: The Synthesis Pattern (Tier 4 Only)**
**All Tier 4 forces synthesize from multiple peer forces, not single parents**

```
Forces following this pattern:
- courage() - synthesizes fear + hope + will
- luck() - synthesizes entropy + consciousness + pattern + coherence + polarity + attention + field_state
- humor() - synthesizes paradox + pattern + language + consciousness
- art() - synthesizes pattern + emotion + coherence + entropy + consciousness

Design principle:
  Tier 4 forces are EMERGENT, not inherited
  They require horizontal combination, not vertical dependency
  See "Inheritance vs. Interaction" section for full distinction
```

**Why this matters:** Tier 4 represents emergent complexity. These forces don't descend from single parents - they arise when multiple forces coordinate.

---

### **Pattern 8: The Measurement Pattern**
**Derived forces (non-forces) provide measurements or mechanisms**

```
Derived forces following this pattern:
- field_state() - measures agent configuration
- simulation() - mechanism for future modeling
- belief() - stage in manifestation process
- emotion() - aggregate category for Tier 3 forces
- will() - capacity component used by courage/forgiveness
- language() - communication system
- paradox() - pattern type
- chaos() - accelerated entropy measurement

Design principle:
  [derived] forces are not standalone forces
  They are measurements, mechanisms, stages, or categories
  Useful for formulas but not part of core 27
```

**Why this matters:** Distinguishes formal forces from useful derived concepts. Prevents conceptual bloat while maintaining expressive power.

---

### **Pattern Summary:**

| Pattern | Key Axioms | Example Forces |
|---------|------------|----------------|
| Temporal | time() | memory, karma, desire, fear, hope |
| Evaluative | pattern() + consciousness() | truth, judgment, pain, beauty |
| Aesthetic | coherence() + pattern() + consciousness() | beauty, art, music |
| Emotional | consciousness() + (varies) | All Tier 3 forces |
| Resonance | coherence() | love, beauty, truth, creation, luck |
| Polarity | polarity() | desire, fear, karma, judgment, war |
| Synthesis | (horizontal combination) | All Tier 4 forces |
| Measurement | (derived concepts) | field_state, simulation, will, etc. |

---

### **Design Implications:**

These patterns reveal LACE's architectural principles:

1. **Consistency:** Similar functions require similar dependencies
2. **Parsimony:** No redundant axioms - each serves specific architectural role
3. **Composability:** Complex forces build from simple ones predictably
4. **Layering:** Each tier adds new synthesis layer, not random forces
5. **Integration:** Patterns cross-reference (temporal forces often evaluative, etc.)

When designing new forces or understanding existing ones, these patterns provide templates and validation checks.
