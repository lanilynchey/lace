# Key Decisions Made

These are design choices LACE has committed to:

## **1. Python as Primary Language**
- Readable by broad audiences
- Good for both pseudocode and execution
- Strong visualization/simulation libraries
- Easy to expand into apps/tools later

## **2. Illustrative First, Executable Second**
- Start with clear pseudocode that teaches concepts
- Define precise data models
- Gradually make functions executable
- Avoids getting bogged in implementation details early

## **3. Philosophical Framework + Computational Notation**
- Not just notation (too abstract)
- Not just philosophy (too vague)
- Hybrid: rich explanation WITH precise function signatures

## **4. Four-Tier Hierarchy**
- Preserves the primordial → emergent structure
- Makes inheritance clear
- Allows for future expansion within tiers

## **5. Open Source (Eventually)**
- Currently private during structure-building
- Will open to contributions once foundations are solid
- License: Creative Commons Attribution-NonCommercial-NoDerivatives 4.0 International (CC BY-NC-ND 4.0)

## **6. Self-Consistent Model (Not Absolute Truth Claims)**
- LACE is a self-consistent model
- Explicitly framed as "this is one way to see reality"
- Welcomes alternative interpretations
- Remains falsifiable and refinable

## **7. Persistent Patterns Over Soul Contracts**
- Framework explicitly rejects soul contract terminology
- Uses "persistent patterns" - editable state encodings, not pre-fated agreements
- Emphasis on probability biasing through current state, not pre-determination
- Maintains agency and Generative Awareness (ability to edit one's own code)
